## Принятые ограничения

**A07 — особенность, не ошибка.** Inference-mid калибрует порог по текущей Matrix и проверяет ту же Matrix. Первые N строк (sample 0) считаются target независимо от MatrixClasses. Этот контракт сохраняется; отдельный held-out набор не входит в обязательный план исправлений. Полученные оценки описывают качество на калибровочном наборе.

**A12 — отложенная особенность численной реализации.** Предполагается достаточно малый шаг. Для NAperiodicLink alpha=1/(Tau*TimeStep); explicit Euler устойчив при 0<alpha<2, монотонен при alpha<=1. Замена схемы/guard сейчас не требуется; большой шаг в контрпримере нарушает предположение.

## Текущий контракт обучения

Оба учителя совместно настраивают длины и амплитуды в фазе 0. Фаза 1 не назначается. TL использует отдельные дендриты; Branch — точки ввода одного дендрита и обратный порядок импульсов. Best-effort выходы означают, что Need=0/Done не доказывают выполнение всех sync/amp допусков и избирательность.

Defaults: EnablePostTrainTuning=true, AutoScaleIterationGap=true. Старые XML наследуют их; PostTune=0 сам по себе не воспроизводит старый pin. TL PostTune=3, Branch=4, Done=2; Branch legacy CalibrateLtz=3 при PostTune OFF. Search делает ScaleTipR для snapshot. [Тайминг](docs/TIMING_AND_GAP.ru.md): gap=span+settle+slack, delay=settle+slack.

## Что изменили новые коммиты Branch

- После выбора BestTips запускается новый free-run: обычный путь A09 частично исправлен.
- Плохой finite landscape оставляет silent-порог и при inference; Search Train с включённым mid оставляет silent всегда.
- После Train Finalize выставляется InferenceMidDone, исключая второй mid в том же процессе; Test-калибровка предполагает новый процесс/reset.
- При free-run reject восстанавливается snapshot, но flag сохраняет метрики отклонённого best. Setup failure завершает процедуру на нулевых метриках. NaN foil всё ещё допускает mid=0.495 при target=0.5.
- Обычный TimeLearner не получил эти изменения; явный LTZ mode в Branch всё ещё не соблюдается.

Восемь новых изолированных Branch-проб: пять PASS, три FAIL. Это проверка извлечённых тел методов с адаптерами, не полный cold-run. Подробности в отчёте.

## Открытые измерительные дефекты

A01–A06: analyzer принимает полноту как 1 или >=4 наблюдавшихся стимулов, может закрепить ранний fire и сменить label незакрытого trial; своевременный ответ обрывает late-наблюдение. Один spike может попасть в несколько per_stim окон. Python strict игнорирует ранний одиночный foil-spike при нулевых fire/late-флагах; last_pulse_ok использует 0.8*max(ISI). Эти исходники не менялись.

Исторический ok_audit допускает 4/8 и не равен идеальной избирательности. Повторный пересчёт первичного среза: 175 CSV, 106 ok_audit, 60 полных strict 8/8. Среди принятых ok_audit+legacy_last_pulse не найден target раньше sum(ISI); это не устраняет потерю событий в analyzer.

A08–A10: остались validity, error paths, соответствие весов/метрик и выбор физического сигнала. A16: verifier не обеспечивает все заявленные ожидания, может прочитать старый CSV после child failure и сравнивает TipR строками. Численно равные 2e7/20000000 дают diff; diff с другим keep-клоном совместим с откатом к собственному snapshot.

## Как читать результаты

PHASE12 содержит 12 VALIDATED (включая две LtzCal-копии) и 20 VALIDATED_CLONE. Это не 32 независимых cold-обучения. Pins PHASE12, RELIABILITY_MAP и текущего кода различаются.

Новый RESULT с timestamp 16:47:46Z содержит только br100_search; предыдущие br25_on/asym25 skip_train выделены отдельно. Parameters/CSV br100_search не изменились относительно e63cdcd7; новых локальных flag/полных логов и binary hash нет. Заявленный свежий запуск независимо не подтверждён, но не объявлен отсутствующим.

Сокращение gap в 6 раз не доказывает ускорение wall: приведённые 85/90 секунд соответствуют примерно 1.06. Для оценки скорости нужны сопоставимые повторения одинаковой завершённой работы.
