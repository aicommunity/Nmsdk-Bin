# Повторные прогоны классификаторов без пачечных выходов

Дата: 2026-09-28. Клоны запущены через Release `NeuroModelerConsole.exe`, по три процесса максимум. В этих replay обучение выключено; исходные синапсы, длины ветвей и физические параметры сохранены. В клонах менялся только фиксированный порог LTZone и настройка пассивной записи. CSV содержит фактические выходы `NeuronTrainerN.Neuron.LTZone.Output`.

## Что проверялось

| Семейство | Порог | Структуры/примеры | Результат по фронтам LTZone |
|---|---:|---|---|
| `NSpikeClassifier`, синтетические прототипы | 0,0085 | три чистых прототипа | три правильных one-hot ответа, по одному фронту; пачек нет |
| `NSpikeClassifier`, Iris | 0,0085 | 10 входов: ID 22, 37, 45, 60, 64, 84, 90, 111, 129, 134 | пачек и многобитных строк нет; 8 строго правильных ответов, ID 111 молчит, ID 134 даёт неверный класс |
| `NSpikeClassifier`, число синапсов на ветви длиной 17 | 0,0085 | 6, 12, 24 или 37 синапсов; торможение On/Off | ни у одного выхода нет больше одного фронта за окно. При 6 синапсах ответ класса 2 исчезает; при 12/24/37 первые три чистых входа дают `100/010/001`, четвёртый — `000`. On/Off совпадают по битам |
| `NSpikeClassifier`, длина ветви 2 класса 2 | 0,0085 | длины 3, 8 и 17, 37 синапсов | подтверждены прежние результаты: пачек нет; длина 17 отвечает на три прототипа one-hot, короткая и средняя структуры теряют/добавляют ответы |
| `NClassifier` и выходные OR-нейроны | 0,0035 / 0,006 / 0,0085 | три входа, по одному из трёх классов; в модели по четыре обучающих нейрона на класс | пачки сохраняются. Выходные счётчики по строкам: `5/4/3; 3/4/5; 5/5/3`, `4/3/3; 2/3/2; 2/4/2` и `3/0/0; 0/2/2; 0/2/2` соответственно |
| `NClassifier` | 0,0117 | те же три входа; контролировались 12 дочерних нейронов и 3 OR-выхода | пачек нет ни у одного из 15 сигналов; OR-ответы `100/010/001`, по одному фронту целевого выхода |
| `NPCAClassifier` | 0,0085 | однопаттерновый replay | для всех 80 строк выходные биты совпали с LTZone-трассой; пачек нет. 66 строк активны, 14 молчат; это не оценка многоклассовой точности |

Значения порога нельзя переносить между типами и топологиями вслепую. `NSpikeClassifier` в этих сохранённых моделях использует `NSPNeuron`, тогда как проверенный `NClassifier` — `NSPNeuronGen`. `0,0085` устраняет пачки в исследованных вариантах `NSpikeClassifier`, но на отдельных входах гасит ответ; `0,0117` даёт одиночный OR-ответ на трёх проверенных входах `NClassifier`. Это критерий кратности, а не гарантия разделимости. В Iris на `0,0085` нет пачек, но остаются один пропуск и одна неверная классификация.

## Проверка связей рекордера

Первый вариант части клонов унаследовал устаревшую карту диагностических сигналов: alias с `_ltz` указывал на `Source*.Output`, а не на `NeuronTrainerN.Neuron.LTZone.Output`. Его счётчики нельзя использовать. Корректные повторы находятся в этом каталоге: в `Model_00.xml` у каждого `NSpikeClassifier`-клона ровно три recorder-связи, и их сериализованные источники сверены с заголовком CSV. При замене пробников сохраняются остальные fan-out-получатели, включая входы тренеров. Клоны Iris и три конфигурации `NClassifier`/`NPCAClassifier` из соседнего [`BurstReplay_20260928`](../BurstReplay_20260928/README.md) также проверены по фактическим путям источников.

Файл [`burst_replay_summary.csv`](burst_replay_summary.csv) и `signals.csv` в каталоге каждого клона содержат машинно-проверяемые результаты. Сводка также сверяет факт каждого выходного бита с фронтами LTZone в соответствующем ответном окне; несоответствий нет. Вне строк `output_data.txt` трасса продолжает мониторить возможные дополнительные окна.

## Повтор и live-мониторинг новых прогонов

Подготовка этих клонов и проверка порядка link-ов выполняется так:

```powershell
python Bin/Configs/SpikeSamples/StructTrain/_repro/ClassifierDynamicsAudit_20260928/prepare_burst_exclusion_replays.py `
  --only fixed `
  --output-root Bin/Configs/SpikeSamples/StructTrain/_repro/BurstReplayVerified_Rerun
```

Генератор отказывается перезаписывать результаты. После EOF приложение сохраняет `DataFromFile=0` в Model и Parameters, поэтому повторно запускать завершённый каталог напрямую нельзя: подготовьте свежий `--output-root` либо верните `DataFromFile=1` в обеих XML-копиях. Для нового полного набора создайте свежий каталог генератором:

```powershell
python Bin/Configs/SpikeSamples/StructTrain/_repro/ClassifierDynamicsAudit_20260928/prepare_burst_exclusion_replays.py `
  --only all `
  --output-root Bin/Configs/SpikeSamples/StructTrain/_repro/BurstReplayVerified_Rerun
```

Запускайте конфиги через [`run_burst_excluded_batch.py`](../ClassifierDynamicsAudit_20260928/run_burst_excluded_batch.py): его каталог по умолчанию совпадает с `BurstReplayVerified_Rerun`; runner ограничивает волну тремя Release-консолями, читает `signals.csv` во время расчёта и сразу сообщает число восходящих фронтов в каждом ответном окне. После завершения собрать сводку можно [`analyze_burst_replays.py`](../ClassifierDynamicsAudit_20260928/analyze_burst_replays.py); скрипт считает переходы `0 -> 1`, сверяет окна с `output_data.txt` и сохраняет CSV.

Пример запуска уже созданных копий:

```powershell
python Bin/Configs/SpikeSamples/StructTrain/_repro/ClassifierDynamicsAudit_20260928/run_burst_excluded_batch.py `
  --project-root Bin/Configs/SpikeSamples/StructTrain/_repro/BurstReplayVerified_Rerun `
  --batch-size 3 `
  NSpikeSynapseCount_Syn6_On_Threshold00085_20260928 `
  NSpikeSynapseCount_Syn6_Off_Threshold00085_20260928 `
  NSpikeSynapseCount_Syn12_On_Threshold00085_20260928
```

В выполненных запусках консоль после записи результатов завершилась с `0xC0000005`; модельное время, `output_data.txt`, полные CSV-трассы и соответствие битов сохранены. Этот код завершения отмечен отдельно и не интерпретировался как успешное штатное закрытие процесса.
